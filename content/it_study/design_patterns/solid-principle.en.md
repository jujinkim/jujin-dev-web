There is an important principle called `SOLID` in object-oriented development. Although you can develop without following it, adhering to it enables more efficient development and maintenance.

In fact, it is not an exaggeration to use the expression "tremendously". Therefore, it is recommended to study, realize, and always keep this principle in mind when creating and modifying new features. By the time we understand this principle, we will have become "Software Programmers" rather than "Coders - Feature Implementers".

SOLID does not literally mean "hard, solid", but is an acronym derived from the first letters of five important principles. The meanings of each letter are as follows. If you don't understand what they mean just by looking at this part, that is normal.

- **S**: Single Responsibility Principle
	- A class should have responsibility for only one reason to change.
- **O**: Open-Closed Principle
	- Classes should be open for extension but closed for modification.
- **L**: Liskov Substitution Principle
	- There should be no problem even if a parent class is substituted with a child class.
- **I**: Interface Segregation Principle
	- Interfaces should be separated by role.
- **D**: Dependency Inversion Principle
	- Dependencies between class implementations and clients should be inverted by abstraction.
